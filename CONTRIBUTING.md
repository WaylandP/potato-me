# Contributing to potato-me

Contributions can improve the editor, fix how a part fits or add new artwork. The app has no runtime dependencies or build step. Start with:

```bash
git clone https://github.com/WaylandP/potato-me.git
cd potato-me
npm run dev     # http://localhost:5173
npm test        # Node's built-in test runner
```

Node 20 or newer runs the server and tests. The optional image tools (`npm run assets`, `npm run hero`, `npm run shot`) need Playwright: `npm install --no-save --package-lock=false playwright sharp && npx playwright install chromium`.

## Where things live

```
index.html            the editor
fit.html              fitting page for part transforms
assets/parts/         rendered parts, 1024 px transparent PNGs on a shared canvas
assets/thumbs/        256 px copies for the option grids (generated by npm run assets)
assets/manifest.json  inventory of the parts: group, key, placement box, checksum
src/assets.js         static index of the parts (generated by npm run assets)
src/fit-data.js       per-shape transforms, recolor lists, cap text boxes, lid corners
src/raster.js         the compositor
src/surface.js        silhouette fitting, skin harmonization and contact shading
src/options.js        every choice the editor offers, plus the defaults and presets
src/state.js          validate state, encode/decode the URL hash, randomize, migrate old links
src/main.js           the editor UI
src/parts/            SVG backgrounds and fallback sticker art
scripts/              dev server, thumbnail builder, screenshot and hero tools
test/                 node:test suites
```

## Adding a part

Parts are generated with an image model, one part per image, positioned as if it sat on the base potato (`assets/parts/body/classic-russet.png`). Read `docs/IMAGE_PROMPTS.md` for the original design guide and `docs/PUBLIC_AUDIT_PROMPTS.json` for the replacement artwork used in v0.4.0. New hairstyles, shapes and accessories are recorded in `docs/expansion-prompts.json` and `docs/cohesion-prompts.json`.

1. **Register the key.** For a brand-new option, add it to the right group in `OPTIONS` (`src/options.js`). Keys end up in share links, so pick a name you can live with.
2. **Generate the image.** Use the master prompt and the part's line from `docs/IMAGE_PROMPTS.md`. Hats, neckwear, headphones and the mug are rendered in the red master color so the app can recolor them; arms in russet skin. Keep the laptop lid and the sign blank.
3. **Normalize it.** 1024 × 1024, RGBA, transparent background, placed where it belongs on the canvas. Save it as `assets/parts/<group>/<key>.png`.
4. **Record it.** Add an entry to `assets/manifest.json` (copy a neighbour; `placedBox` is the opaque bounding box) and run `npm run assets`. To update only changed thumbnails, use `npm run assets -- neckwear/scarf hat/backwardCap`; the complete index is always rebuilt.
5. **Fit it.** Body labels live in `BODY_PROFILES`; keep historical share keys unchanged (`long` = Petite, `petite` = Wide). Inspect enlarged blue/purple faces and gripping fingers so golden mask remnants are visible.  Open `fit.html`, look at the part on Classic, Lumpy, Round, Petite, Pear and Wide, nudge with the arrow keys, and paste the printed `surfaceNudges` into `src/fit-data.js`. Red colorway parts also go in `FIT.recolor`; use `FIT.skinProtect` polygons to preserve held objects while their hands remain tintable. Calibrate `FIT.palmWidth` against the visible hand, and preserve fingers crossing the body with `FIT.skinFront`. The surface renderer samples the selected body for a shared limb material palette; protect objects in source-image coordinates. A two-sided part that was rendered too close together (earbuds) takes a `spread` instead of a scale, and a part that should scale around its own point gets a `group/key` entry in `FIT.pivots`.
Automatic placement is in `src/surface.js`: it anchors arms inside the body silhouette, aligns face parts to shared landmarks, seats hats and worn accessories, and flexes headphone bands while preserving ear cups. `FIT.shapes` and `FIT.parts` retain baseline sizing; `FIT.surfaceNudges` applies manual corrections after this fit. For a reversed or unusual arm, record its actual shoulder in `FIT.surfaceRoots`.

6. **Check it.** `npm test`, then `npm run shot review.png spec.json --cell 256 --cols 4` with a few combinations, and look at them in the avatar crop and the thumbnail grid. For an inventory-wide review, run `npm run audit -- /tmp/potato-art-audit inventory`. It writes review sheets and a JSON report, exercising full PNG exports, thumbnails and share-state round trips for every asset. Passing checks do not replace viewing the sheets. Run the affected interaction modes (`headwear`, `expressions`, `facial-hair`, `eyewear`, `poses`, `colors`, `backgrounds`, `details`, `hair`, `pairwise`) and `npm run audit:ui -- /tmp/potato-ui`; see [EVERYDAY_AUDIT.md](docs/EVERYDAY_AUDIT.md) for the historical matrix definitions and [WRAP_REVIEW.md](docs/WRAP_REVIEW.md) for the current headgear scope.

The faster `npm run audit:cohesion -- /tmp/potato-cohesion` uses Sharp and Chromium to check each asset on all 54 body/skin contexts at 256 px. It checks crop bounds and share round trips; it does not replace 1024 px inspection or PNG export tests. Optional trailing group names limit the run.

The current attachment audit is `npm run audit:attachments -- /tmp/potato-attachments inventory`. Its `materials`, `interactions` and `reported` modes cover material palettes, hairstyle/accessory stacks and the reported flower-crown look. Use `--plan` for the exact case list. `AUDIT_GROUPS`, `AUDIT_MATCH` and `AUDIT_LIMIT` select an explicit subset; reports record those filters so a partial run cannot be mistaken for complete coverage. `AUDIT_SIZE=1024` produces native proofs, `AUDIT_SOURCE=full|thumbs` selects actual source files, and `CHROME_EXECUTABLE` selects an installed Chromium binary. Inspect the resulting contact sheets and enlarge suspicious boundaries. See [ATTACHMENT_REVIEW.md](docs/ATTACHMENT_REVIEW.md).

Run `npm run audit:color-framing -- /tmp/potato-color-framing` after changing recoloring or framing. It compares actual Chromium renders and original/copy geometry across every bun color and body, using full and thumbnail sources plus native proofs. Register recolored canvases against their original image with `registerFramingSource`; the camera must not depend on differences in how the browser downsamples an Image versus a Canvas. The optional audit rejects an occupied server port before rendering.

For grip artwork or arm changes, run `npm run audit:grips -- /tmp/potato-grips all`. Its `native`, `matrix` and `inspiration` modes retain native hand proofs, compare book/donut/coffee/sign/trophy across every body and skin through actual 512 px export and 192 px thumbnail paths, and render all inspiration definitions. `--plan` records exact coverage; `AUDIT_PORT`, `CHROME_EXECUTABLE`, `AUDIT_GROUPS`, `AUDIT_MATCH` and `AUDIT_LIMIT` configure explicit subsets. Inspect finger opposition, object support and wrists in the saved images. Root overlap and plausible transforms do not prove a convincing grip. See [GRIP_REVIEW.md](docs/GRIP_REVIEW.md) and [grip-image-prompts.json](docs/grip-image-prompts.json).

### Art checklist

- Offer every style on every body shape. Keep labels understandable without developer jargon. Preserve existing share keys.
- Hair must follow the crown and leave a usable face opening; hats occlude it with their silhouette, never a straight crop. Earrings sit beneath long hair.
- Neckwear must wrap the broad upper torso with sides turning behind it: no narrow human-neck ring. Keep knots, collars and gravity-correct tails proportionate.
- Same camera, scale and upper-left light as the base potato. Straight-on front view.
- Only the requested part in the image. No potato, no shadow, no text, no background.
- Original designs only. No logos, mascots or characters from other brands.
- Eyes contain no eyebrows and eyebrows no eyes; only thin skin-colored edges on eyelids and lips.
- Held items include the viewer's-left arm and hand; gestures the viewer's-right arm and hand.

## Pull requests

- Keep each PR focused. For visual changes, include screenshots on all six body shapes and representative skins, plus the avatar crop. Inspect contact points, grips, skin edges and accessory overlaps; passing exports alone does not prove the artwork fits. The PR template has a checklist.
- Keep README.md and CHANGELOG.md accurate. Mark ROADMAP.md work shipped only after it is built, tested and verified on the deployed site.
- Commit messages in plain English: what changed and why.

## Reporting bugs

Open an issue with the share link from the address bar. The link contains the exact potato, which makes rendering bugs easy to reproduce.

### Wearable fitting

Measure the wearing opening separately from the outer artwork bounds. `FIT.hatOpenings` and `FIT.hairOpenings` store source-space landmarks; `surface.js` fits them to the actual body and selected hairstyle. Brims, pom-poms and ponytails are not head width. Keep eye clearance, temple contact and crown height in view when fitting short or narrow bodies.

Hair uses continuous inverse mapping with premultiplied bilinear sampling. Do not replace it with independently shifted row strips: those created visible seams and stepped strands. `fittedPoint()` shares the geometry with framing and tests. A receiver silhouette in `raster.js` ensures shadows land on already-worn layers, including hair. Regenerate thumbs and update manifest checksums after replacing a PNG.

Rear interiors are measured separately in `FIT.wrap`, in source-image coordinates. `src/wrap.js` splits those regions from the original image; both pieces use the same fitted transform. Draw a rear brim behind the body, or a headphone band behind the hair, and keep its front piece in the ordinary layer order. Do not apply a generic bottom-strip deletion: the Santa/beanie/chef cuffs and the barrette leaf are front decoration. Headphone cups start near source y455 and must remain entirely in front. Review source-sized contact proofs as well as thumbnail sheets after changing a mask. The current examples and scope are in [WRAP_REVIEW.md](docs/WRAP_REVIEW.md).
